# 코딩 규칙

## 공통

- 기존 스타일을 유지한다. 새 패턴을 도입할 때는 `_workspace/99_decisions.md` 에 이유를 남긴다.
- 중복 코드를 만들지 않는다. 두 번 이상 반복되면 함수 또는 모듈로 분리한다.
- 불필요한 의존성을 추가하지 않는다. 현재 런타임 의존성은 **0개**(devDependency: electron)를 유지한다.
- 주석은 "왜"만 적는다. 코드가 이미 말하는 "무엇"을 반복하지 않는다.
- 저작권/라이선스 헤더를 임의로 추가하지 않는다.

## JavaScript

- 모듈 시스템
  - 메인/스크립트: CommonJS (`require`)
  - 렌더러: ESM (`import`), `<script type="module">`
- `'use strict'` 는 CommonJS 파일에 사용하지 않는다(모듈 스코프로 충분).
- 비동기: `async/await` 사용. `new Promise` 안에서 `reject` 를 빠뜨리지 않는다.
- 오류: 잡은 오류는 반드시 (a) 사용자 메시지로 변환하거나 (b) 로그로 남기거나 (c) 다시 던진다. 조용히 삼키지 않는다.
- 입력 검증: IPC 경계에서 모든 payload 를 검증한다(타입·허용값·길이). SQL 은 반드시 `bind`/파라미터 사용.
- 문자열 조합으로 SQL 을 만들지 않는다.
- 시크릿을 `console.log` / 오류 메시지 / DB 평문 컬럼에 넣지 않는다.

## Electron

- 렌더러에서 Node API 를 직접 쓰지 않는다. 반드시 preload 의 화이트리스트 IPC 를 통한다.
- `ipcRenderer` 자체를 노출하지 않는다. 채널 이름을 노출하지 않고 의미 있는 함수만 노출한다.
- 메인 프로세스의 긴 작업(수집·AI 호출)은 이벤트 루프를 막지 않도록 비동기로 처리하고 진행률을 전송한다.
- `spawn` 은 셸 없이 인자 배열로만 실행한다(`shell: false`).

## CSS

- 색·간격·반지름·폰트 크기는 `tokens.css` 변수만 사용한다. 하드코딩하지 않는다.
- 클래스 이름은 `block__element--modifier` 대신 짧은 `kebab-case` 를 사용한다.
- 레이아웃은 `layout.css`, 컴포넌트 외형은 `components.css`, 뷰별 배치는 `views.css` 에 둔다.

## 접근성·UX

- 모든 버튼은 `type="button"` 을 명시한다.
- 아이콘만 있는 버튼에는 `aria-label` 을 붙인다.
- 로딩 중에는 버튼을 비활성화하고 진행 상태를 텍스트로 표시한다.
- 파괴적 동작(삭제, 전체 초기화)은 확인 대화상자를 거친다.
