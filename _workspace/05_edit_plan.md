# Edit Plan

## 목표

`UI.png` 목업과 일치하는 Electron + SQLite 영어 학습 앱을 신규 구축한다.
채널 수집 → 듣기/자막 학습 → 문장 저장·AI 분석 → 누적 목록 → 공유 → 설정까지 한 흐름으로 동작시킨다.

## 작업 범위

1. 프로젝트 골격: `package.json`, Electron 설치, 인코딩/EOL 설정
2. 메인 프로세스: 창, 커스텀 프로토콜, 보안 정책, IPC, 로깅
3. 데이터: SQLite 스키마·마이그레이션·쿼리, 설정/비밀값 저장
4. 수집: 자막 파서 → yt-dlp provider → native provider → 오케스트레이터
5. AI: OpenRouter 모델 목록 + 구문분석(JSON) + 오류 정규화
6. 공유: 내보내기(JSON/MD/HTML) + 가져오기(JSON 병합)
7. 렌더러: 디자인 토큰 → 셸(타이틀바/사이드바) → 컴포넌트 → 뷰 7종
8. 검증: 단위 테스트, Electron 스모크(+스크린샷), 실제 채널 수집 실측
9. 기록: 구현 로그, 검증 보고서, 변경 이력, 보류 항목

### 수정 순서와 근거

1. **원인 규명 먼저**: 재생 실패를 네트워크로 단정하지 않고 `_tmp` 프로브로 `app://` / `http://127.0.0.1` 두 조건을 비교했다. `app://` 는 항상 `error 153`, loopback HTTP 는 정상 → 원인은 Referer 누락이었다.
2. **근본 원인 수정**: 메시지 문구를 바꾸는 대신 서빙 방식을 바꿨다. 문구만 바꾸면 재생은 여전히 실패한다.
3. **회귀 방지**: 원인을 재현하던 조건을 `scripts/e2e-player.js` 로 고정해 자동 검증한다.
4. **옵션은 기본 켜짐**: 기존 동작(항상 최신 메타)을 기본으로 유지해 기존 사용자 흐름을 깨지 않는다.

| 후속 | "채널 한 번 불러오고 새 데이터만 저장 가능한가" | 추가 구현 없음(T26 `refreshExisting` 로 이미 충족) | 채널 E2E 재수집 단계 |

### 수정 순서와 근거

1. **원인 먼저 측정**: 검은 레이어는 추측으로 고치지 않고 DOM 프로브로 `.player-frame`/`.player-caption` 의 `getBoundingClientRect()` 를 zoom 0/+1/-1 에서 비교했다. 자막 상자가 프레임과 같은 376×211 이라는 사실이 곧 원인이었다.
2. **가정 대신 근거**: "네트워크가 느려서 전체를 못 긁었다" 가 아니라 기본 상한 24 가 그대로 적용된 것이므로, 상한 자체를 기본 해제하는 쪽으로 고쳤다. 개수 제한은 옵션으로 남긴다.
3. **한 경로만 고치지 않음**: yt-dlp 와 native 두 provider 모두 상한 로직이 있으므로 양쪽을 같은 규칙(`Number.isFinite(limit)`)으로 맞췄다.
4. **부분 실패 허용**: 전체 수집은 오래 걸리므로 채널별로 순차 실행하고, 한 채널이 실패해도 나머지를 계속 진행한 뒤 집계 토스트를 한 번만 띄운다.

| 1 | OpenRouter 모델을 불러올 때 **가격도 함께 표시** | `main/ai/openrouter.js`(가격 파생 필드) + `renderer/js/views/settings.js`(선택 목록/행 표시) + `renderer/css/views.css` | 단위 테스트(가격 라벨·단가 환산) + 스모크(모델 행 가격 텍스트) |

### 수정 순서와 근거

1. **가공은 메인 한 곳에서**: OpenRouter 응답의 `pricing.prompt`/`pricing.completion` 문자열은 이미 IPC 로 넘어오고 있었다. 화면에서 문자열을 다시 해석하면 뷰마다 규칙이 갈라지므로, `main/ai/openrouter.js` 의 매핑 단계에서 `priceLabel`·`priceShort`·`priceScore`·`valueRank`·`searchText` 를 만들어 내려보낸다(D-017 과 같은 이유).
2. **가격 미정을 0원으로 취급하지 않는다**: OpenRouter 는 라우팅 모델(`openrouter/auto`)의 가격을 `"-1"` 로 준다. 이걸 그대로 쓰면 "무료" 로 잘못 표시되므로 음수는 "가격 정보 없음" 으로 다루고 가성비 순위 뒤로 보낸다.
3. **추천과 선택을 분리**: 추천 목록은 가성비 상위 5개만 보여 주고, 전체 목록은 검색어로 좁혀서 고른다. 두 목록 모두 같은 행 컴포넌트(`.model-row`)를 쓰고 클릭 한 번에 기본 모델로 저장한다.
4. **검색은 입력 즉시**: 별도 버튼 없이 `input` 이벤트에서 목록만 다시 그린다(기본 모델 `<select>` 는 다시 만들지 않아 입력 포커스와 스크롤이 유지된다).

### 수정 순서와 근거
(6차)

1. **기존 목록을 다시 만들지 않는다**: 채널 개수는 이미 있는 `channels` 조회 경로에서 계산한다. 뷰에서 영상/자막/문장을 따로 세면 화면마다 숫자가 어긋나므로, DB 한 곳에서 세고 모든 읽기 경로가 같은 값을 돌려주게 했다. 그래서 `main/ipc.js` 는 손대지 않았다.
2. **한 버튼에 두 동작을 얹지 않는다**: 줄 클릭은 사용자가 이미 "그 지점부터 재생" 으로 기대하고 있었다. 전송을 클릭에 얹으면 재생하려다 보내지므로 동작을 분리하고, 버튼에서 `stopPropagation` 으로 줄 클릭을 막았다.
3. **이동과 재생을 함께**: `player.seekTo()` 는 위치만 옮기고 재생을 시작하지 않아 "눌러도 소리가 안 나는" 상태가 된다. 줄 클릭은 `seekTo` + `play` 를 함께 호출한다.
4. **문장 패널 포커스는 전송할 때만**: 드래그 선택(`onSelect`)은 입력 포커스를 유지해야 하므로 `selectSentence` 에 `focus` 옵션을 두고, 전송 버튼 경로는 `focus:false` + 성공 토스트로 처리했다.

## 8차 라운드 수정 계획 (수집 중 정지)

| 항목 | 요청 | 수정 지점 | 검증 |
|---|---|---|---|
| 1 | 자막 2000개 이상 수집 중 **정지**할 수 있게 | `main/collect/job-registry.js`(신규) + `main/collect/index.js`·`net.js`·`ytdlp-provider.js`·`native-provider.js`(signal 전파) | 단위 테스트 6건 + 취소 E2E(즉시성·부분 결과 보존) |
| 2 | 진행 중 **정지 버튼** 노출 | `renderer/js/views/channels.js`(`cancelInline`, `paintCancelButtons`) | 스모크(`view:channels 정지 버튼`) |

### 수정 순서와 근거

1. **먼저 끊을 수 있게 만든다**: 취소 플래그만 세우는 방식은 루프 경계에서만 검사돼 자막 1건(최대 150초)을 기다린다. `AbortSignal` 을 자식 프로세스(`ytdlp-manager.run`)와 네트워크(`net.fetchText`)까지 넘겨 중단 지점을 안쪽으로 옮겼다.
2. **상태는 한 곳에**: jobId 단위 취소 플래그와 `AbortController` 를 `job-registry.js` 로 모아 새 provider·새 호출을 추가할 때 배선 누락을 찾기 쉽게 했다(`ytdlp-manager.run` 의 signal 인자가 호출부에서 쓰이지 않던 dead code 를 제거).
3. **정지는 되돌리기가 아니다**: 취소 시점까지 저장된 영상·자막을 유지하고 `cancelled:true` + partial 값을 반환·`error.detail` 로 전달해 화면이 `실패` 와 `취소됨` 을 구분한다.
4. **버튼 상태는 한 함수에서**: 진행/전체 수집/정지 세 버튼의 hidden·disabled·문구를 `paintCancelButtons(busy)` 가 관리해 조합(진행 중·정지 요청 중·대기)마다 조건문이 흩어지지 않게 했다.

| 1 | 자막을 하나씩 내려받아 **너무 느린 문제** 개선 | `main/collect/index.js`(자막 단계 워커 풀) + `main/collect/ytdlp-provider.js`(자막 언어 후보 축소) + `main/db/settings.js`·`main/ipc.js`·`renderer/js/views/settings.js`(동시 수집 개수) | 실측 프로브(전/후) + 단위 테스트(동시성·부분 실패) + 채널 E2E + 취소 E2E 회귀 |
| 2 | 상단 **`수집 환경` 카드 숨김**(사용자에게 불필요) | `renderer/js/views/channels.js`(`statusCard.hidden`) | 스모크(`view:channels`) + 설정 화면에 같은 정보·내려받기 버튼이 있는지 확인 |

### 수정 순서와 근거

1. **측정 먼저**: `_tmp/probe-subs-speed.js` 로 TED 영상 6개를 ① 한 개씩 ② `--batch-file` 한 프로세스로 받아 비교했다. 결과는 `one-by-one(cold) 66.1s(11.0s/편)` vs `batched 48.1s(8.0s/편)` = **1.37x**. 즉 프로세스 생성 비용을 없애는 것만으로는 부족하고, **네트워크 왕복 대기(편당 8~11초)를 겹치는 것**이 훨씬 큰 지렛대다. 그래서 배치 대신 **동시성**을 택했다.
2. **동시성은 워커 풀로**: 영상마다 `yt-dlp` 프로세스를 하나씩 띄우되 N개를 동시에 돌린다. 배치(`--batch-file`)는 ① 편당 개별 타임아웃이 사라지고 ② 한 편에서 멈추면 배치 전체가 멈추며 ③ 완료 시점을 파일 목록 diff 로만 알 수 있어 진행률·정지 즉시성이 나빠진다. 8차의 "정지가 즉시 먹는다" 계약을 지키려면 편당 프로세스가 유리하다.
3. **취소는 그대로 즉시**: 워커들이 같은 `AbortSignal` 하나를 공유하므로 정지 시 진행 중인 자식 프로세스가 **동시에** 죽는다(8차 계약 유지). 워커 루프 선두에서 `assertNotCancelled` 를 다시 확인해 대기 중인 워커는 새 작업을 시작하지 않는다.
4. **임시 폴더를 편 단위로 분리**: 기존 `fetchSubtitles` 는 `outDir` 하나를 `readdir` diff 로 쓰고 호출 뒤 폴더를 통째로 지웠다. 동시 실행에서는 서로의 파일을 지우거나 남의 자막을 집어오므로 `collect-<jobId>/<videoId>` 로 내려 받는다.
5. **받는 파일 수를 줄인다**: `--sub-langs en.*,en` 은 정규식이라 `en-fr`·`en-hu` 같은 **자동 번역 트랙까지 함께** 받는다(실측: 편당 2~3개). `en` 만 지정하면 정확히 1개만 받는다(실측 4/4). 다만 `en` 트랙이 없는 영상이 있으므로, 파일이 하나도 안 생기면 기존 넓은 패턴으로 **한 번만** 재시도한다.
6. **동시 개수는 설정에서**: 기본 4, 1~8. 네트워크가 느리거나 YouTube 가 제한을 걸면 1 로 낮출 수 있게 설정 화면 `수집 설정` 에 숫자 입력을 추가한다.
7. **내부 상태 카드는 숨긴다**: `수집 환경` 카드는 진단용 정보라 일반 사용자에게는 노이즈이고, 같은 정보와 `yt-dlp 내려받기` 가 이미 설정 화면에 있다. 평소에는 감추고, **yt-dlp 를 쓰기로 했는데 yt-dlp 가 없어 수집이 아예 불가능한 경우에만** 자동으로 나타나게 한다.

## 10차 라운드 수정 계획 (문장 누적 + 저장 없는 AI 분석)

| 항목 | 요청 | 수정 지점 | 검증 |
|---|---|---|---|
| 1 | 선택한 문장을 전송하면 기존 입력이 지워진다 → **추가**되게 | `renderer/js/components/sentence-panel.js`(`appendSentence` 등) + `renderer/js/components/study-workspace.js`(`selectSentence`/`sendSentence`) | 스모크(누적 전송·중복 무시) + 회귀(기존 전송 동작 유지) |
| 2 | 문장을 저장하지 않고 **AI 를 누르면** 그 데이터로 구문분석해 저장하고 바로 보여주기 | `renderer/js/actions.js`(`analyzeAndSaveSentence`) + `renderer/js/components/sentence-panel.js`(`analyze`) + `renderer/js/components/study-workspace.js`(`analyzeSentence`) | 스모크(AI 즉시 저장·결과 표시) + 단위(기존 AI 정규화 회귀) |

### 수정 순서와 근거

1. **덮어쓰기 지점을 먼저 찾는다**: 전송 경로는 `transcript.js` → `study-workspace.sendSentence()` → `sentencePanel.setSentence()` 였고, `setSentence` 는 "저장된 문장을 불러온다"는 의미의 **교체** 동작이다. 전송이 같은 메서드를 쓰니 매번 입력칸이 비워졌다.
2. **누적은 별도 메서드로 분리한다**: `appendSentence()` 를 새로 만들어 **줄 단위 중복 검사 후 `\n` 으로 덧붙인다**. `setSentence` 는 저장 문장을 다시 여는 경로(`renderSentencesTab`)에서 계속 덮어써야 하므로 두 의미를 섞지 않는다.
3. **시각을 문장에 붙여 둔다**: 자막 줄은 전송 시점의 재생 위치를 알고 있지만 그 문장은 나중에 저장된다. 그래서 `startSecs` 맵에 문장별 시각을 기억해 두고 저장할 때 **그 문장의 값**을 쓴다. 전역 `selectedStartSec` 로 폴백하면 2번째 문장이 1번째 시각을 갖게 되므로 폴백을 제거했다.
4. **중복은 조용히 넘기지 않는다**: 이미 들어 있는 문장을 다시 보내면 패널은 그대로 두고 `이미 문장 패널에 있는 문장입니다.` 만 알린다. 스모크가 "2줄 전송 후 같은 줄 재전송 → 여전히 2줄" 로 확인한다.
5. **AI 는 저장을 전제로 바꾼다**: 기존 흐름은 `문장 저장 → 목록에서 다시 열기 → AI 구문분석` 이었다. `analyzeAndSaveSentence()` 가 AI 호출 직후 `sentences.create({ source:'ai' })` 로 저장하고 목록·자료를 갱신한 뒤 결과를 반환하게 해, 사용자에게는 **버튼 한 번으로 분석 + 저장 + 표시**가 끝난다. `analysis`(구조·표현·예문)와 `translation` 을 함께 저장하므로 목록에서 다시 열어도 같은 내용이 보인다.
6. **한 번에 처리할 양을 제한한다**: 여러 줄을 붙여 넣고 AI 를 누르면 호출이 줄 수만큼 나간다. `MAX_ANALYZE_LINES = 5` 로 자르고 초과분은 안내 토스트로 알리며(초과 줄은 입력칸에 남긴다), 진행 중에는 버튼에 `분석 중… 2/3` 을 표시해 멈춘 것처럼 보이지 않게 한다.
7. **기존 API 는 유지한다**: `analyzeSentence`(저장된 문장 단위 분석)와 `sentences.create` 계약은 그대로 두고, 새 경로는 그 위에 얹었다. IPC·스키마 변경이 없어 4~9차 동작에 영향이 없다.

## 11차 라운드 수정 계획 (동영상 목록 검색 + 페이징)

1. **상한의 출처를 먼저 확인한다**: 화면에 200편만 보이는 이유는 DB 가 아니라 `renderer/js/actions.js` 의 `api.videos.list({ channelPk, limit: 200 })` 였다. DB 에는 2000편이 다 있었으므로 "더 가져오기"가 아니라 **요청을 페이지 단위로 바꾸는 것**이 맞는 방향이다.
2. **필터는 한 곳에서 만든다**: 목록과 총계가 다른 조건을 쓰면 `N개 중 i–j` 가 어긋난다. `buildFilter({channelPk, q})` 를 두고 `list`/`count` 가 같은 WHERE·같은 바인딩을 쓰게 한다.
3. **기존 계약은 깨지 않는다**: `videos.list` 는 **배열**을 그대로 돌려준다(테스트·기존 호출부 유지). 총계·다음 페이지 여부가 필요한 화면만 새 `videos:page` 를 쓴다.
4. **한 번에 그리는 양을 고정한다**: 페이지 크기 50. 2000편이어도 DOM 노드가 50개라 스크롤과 모드 전환이 가볍다.
5. **검색은 메인에서 한다**: 2000편을 렌더러로 넘겨 거르면 IPC 페이로드와 메모리가 그대로 커진다. SQLite `LIKE` 로 걸러 **그 페이지 50편만** 넘긴다.
6. **LIKE 와일드카드는 문자로 취급한다**: 사용자가 `%` 를 넣으면 전체가 매칭되는 흔한 버그를 막기 위해 `ESCAPE '\'` 와 `escapeLike()` 를 쓴다.
7. **타이핑마다 조회하지 않는다**: 260ms 디바운스 + Enter 즉시 실행. 조회는 채널을 바꾸거나 페이지를 넘길 때만 일어난다.
8. **늦게 온 응답은 버린다**: 빠르게 타이핑하면 이전 요청의 결과가 나중에 도착할 수 있다. 요청 토큰(`videoPageToken`)으로 최신 요청만 반영한다.
9. **검색 위치는 드롭다운을 대체하지 않는다**: 사용자가 짚은 "TED-Ed · 2.2K videos" 자리는 채널 **선택** 드롭다운이다. 지우면 채널 전환이 불가능해지므로 그 바로 아래에 검색 입력을 둔다.
10. **회귀 방지선을 남긴다**: 단위 테스트(검색·페이징·이스케이프·조건별 count), 브리지 스모크(`videos:page` 총계·hasMore·검색 결과), 화면 스모크(검색/페이저 존재·배치·검색 후 복원).

## 12차 라운드 (AI 구문분석 자동저장 + 분석 노출)

1. **증상을 코드보다 먼저 확인한다**: 실사용 DB(`node _tmp/db-inspect.js`)와 앱 로그(`%APPDATA%\study-ted\logs\app.log`)를 먼저 읽었다. 로그의 429 14연속이 결정적 단서였다.
2. **저장 계층을 의심하지 않는다**: `_tmp/analysis-roundtrip.js` 로 저장 왕복을 먼저 증명해 수정 범위에서 제외했다(원인 B).
3. **일시 오류는 재시도한다**: 429·408·5xx·네트워크 오류만 지수 백오프(2회, 800ms→8s)로 다시 시도하고 `Retry-After` 를 우선한다. 401·400 같은 영구 오류는 즉시 실패시켜 무의미한 대기를 만들지 않는다.
4. **재시도가 안내로 끝나지 않게 한다**: 두 번 다 실패하면 `AI_RATE_LIMIT` + "다른 모델을 선택해 주세요(무료 모델은 사용량 제한이 잦습니다)" 로 원인과 다음 행동을 함께 준다.
5. **저장된 것은 보여야 저장된 것이다**: 분석을 저장만 하고 화면에 그릴 곳이 없던 것이 사용자 체감 "저장이 안 된다"의 절반이다. 문장 노트 표에 `분석` 컬럼을 넣고 행을 펼쳐 해석·구문·표현·예문을 그대로 보여 준다.
6. **실패를 성공처럼 보이게 두지 않는다**: 분석 박스를 비우고 `분석하지 못한 문장` 카드로 실패 문장과 이유를 남긴다.
7. **마크업은 한 곳에 모은다**: 문장 패널·노트 표·자료 목록이 같은 카드를 쓰도록 `analysis-card.js` 로 뽑아 세 화면이 따로 늘어나지 않게 한다.
8. **회귀 방지선을 남긴다**: 단위(재시도 5건) + 화면(노트 분석 표시·펼치기·분석 실패 표시 3건).

## 13차 라운드 (영어 필드 한국어 오염 수정 + 분석 카드 정리)

1. **화면보다 데이터를 먼저 본다**: "전부 한국어로 보인다"는 신고는 렌더러 버그와 모델 오염을 구분해야 한다. 실사용 DB 의 `sentences.analysis_json` 을 열어 보니 정상(id=3)과 오염(id=4: `translation` 이 영상 제목, `structure[].part` 가 한국어 명사구, `examples[].en` 이 한국어)이 섞여 있었다 → **모델이 만든 데이터 문제**로 확정.
2. **모델이 흔들려도 저장되는 값은 지킨다**: 모델을 바꾸라고만 안내하면 8B 무료 모델 사용자는 계속 한국어를 받는다. 프롬프트에 규칙을 명시하고(가장 강한 위치에), 응답을 검증해 **오염된 필드만 정확히 지목해 1회 교정**을 요청한다. 교정이 오히려 나빠지면 첫 결과를 유지한다.
3. **조용히 넘어가지 않는다**: 자동 교정이 실패하면 저장은 하되 카드 상단에 노란 경고로 오염 사실과 다음 행동(다른 모델 선택 후 재실행)을 알린다.
4. **검사는 한 곳에서**: 같은 규칙(한글 포함 여부)을 메인(`findLanguageMismatch`)과 렌더러(`koreanEnglishFields`)가 각각 갖되 판정 대상(`structure[].part`)은 하나로 맞춘다. 예전에 저장된 오염 데이터도 화면에서 바로 보인다.
5. **요청하지 않은 것은 만들지 않는다**: 사용자가 "주요 표현·예문 필요없어 보여"라고 했으므로 스키마·수동 입력·편집기에서 그 필드를 뺀다. 다만 이미 저장된 값은 지우지 않는다(공유 내보내기 호환).
6. **사용자가 볼 필요 없는 것은 화면에서 뺀다**: 하단 `AI 원문 응답` 섹션은 제거하되 `analysis.raw` 는 DB 에 그대로 남겨 문제 진단 여지를 없애지 않는다.
7. **답이 나오는 자리를 넓힌다**: 하늘색 카드의 행 간격·줄 높이·글자 크기·섹션 간격을 키워 구문 설명이 답답하지 않게 한다.
8. **회귀 방지선을 남긴다**: 단위(언어 검증 4건) + 화면 스모크(구문 영어 표시·`AI 원문 응답` 없음 2건).

## 14차 라운드 (문장 노트에서 주요 표현·예문·메모·태그 제거)

1. **"안 보이게"로 끝내지 않는다**: 입력칸만 숨기면 값은 DB 에 계속 쌓이고, 나중에 되살릴 때 지저분한 데이터가 그대로 나온다. 사용자가 "디비에서 빼줘도 돼"라고 했으므로 컬럼과 테이블을 **실제로 삭제**한다.
2. **마이그레이션은 덧붙이기만 한다**: `initial` 마이그레이션의 `CREATE TABLE tags/sentence_tags`·`sentences.note` 는 손대지 않는다(그 버전으로 만들어진 DB 이력을 그대로 재현해야 한다). 두 번째 마이그레이션 `dropSentenceNoteAndTags` 가 `DROP TABLE IF EXISTS sentence_tags` → `DROP TABLE IF EXISTS tags` → `ALTER TABLE sentences DROP COLUMN note` 를 한 번에 실행한다.
3. **계층을 한 번에 걷어낸다**: 화면(표 컬럼·수정 모달·수동 입력) → IPC 계약(`sentences:list` 의 `tag`, `sentences:create/update` 의 `note`·`tags`, `tags:list`) → preload/렌더러 `api` → DB 쿼리(`setTags`·`listTags`·태그 조인) → 공유 내보내기·가져오기 → 데모 시드 → 단위 테스트·스모크까지 같이 정리한다. 한 계층만 남으면 죽은 경로가 조용히 살아남는다.
4. **이름이 비슷한 다른 값을 지우지 않는다**: 없애는 것은 **문장 메모(`sentences.note`)와 태그**다. 분석 카드의 `analysis.structure[].note`(구문 설명, 예: "want to + 동사원형")는 사용자가 요청한 대상이 아니므로 그대로 둔다.
5. **분석 요청도 같이 줄인다**: 새로 분석할 때 표현·예문을 요청하지 않도록 JSON 스키마를 `translation` + `structure` 두 키로 유지하고, `normalizeAnalysis` 도 그 두 키 + `raw` 만 돌려준다.
6. **실데이터로 마이그레이션을 검증한다**: 실사용 DB 사본(영상 2,358 · 자막 144 · 채널 1 · 문장 4)에 실행해 ① `schema_version` 1→2 ② `note` 컬럼 제거 ③ `tags`·`sentence_tags` 제거 ④ 행 수 보존을 확인한다.
7. **회귀 방지선을 유지한다**: 스모크는 태그 expect 2건만 빼고 그대로 돌려 92/0, 단위는 61/61, 채널·재생 E2E 는 8/8·6/6 을 유지한다.

## 15차 라운드 (구문 한국어 뜻 필수 + 단어 분할 금지)

1. **화면보다 데이터를 먼저 본다**: "영어 단어만 나열된다"는 신고는 렌더러·저장 버그와 모델 출력 품질을 구분해야 한다. 실사용 DB 의 `sentences.analysis_json` 을 열어 `structure` 가 **단어 단위**이고 `meaning` 이 **빈 문자열**임을 확인해 모델 출력 문제로 확정했다.
2. **규칙은 프롬프트의 가장 강한 위치에 쓴다**: `systemPrompt` 에 한국어 `meaning`/`note` 필수, `userPrompt` 에 `structure` 3~6개·단어 분할 금지·빈 값 금지를 명시한다. 8B 무료 모델은 규칙을 한 곳에만 쓰면 자주 빠뜨린다.
3. **말로만 시키지 않고 응답을 검증한다**: `findMissingMeaning`(뜻 빈 값)과 `findChunkingProblem`(단어 분할)을 추가해 **저장 전에** 검사한다. 검사 대상은 기존 `findLanguageMismatch`(한글 오염)와 같은 자리(`structure`)로 모은다.
4. **교정은 1회, 더 나아질 때만 채택한다**: 이슈가 있으면 교정 프롬프트로 한 번만 재요청하고, 교정본의 이슈 수가 줄 때만 갈아 끼운다. 소형 모델의 무한 반복을 피하고 실패 시 사용자 대기를 만들지 않는다.
5. **빈 값을 조용히 넘기지 않는다**: 저장은 하되 분석 카드에 ` : 뜻 없음` 과 노란 경고를 띄워 품질 문제를 숨기지 않는다.
6. **이미 저장된 것은 되돌릴 수 없다는 사실을 인정한다**: 소급 복구가 안 되므로 문장 노트에 `AI 다시 분석` 버튼을 조건부로 붙여 사용자가 직접 갱신할 수 있게 한다.
7. **검증 도구의 경합을 버그로 남기지 않는다**: 스모크가 실 AI 호출과 겹쳐 `분석 중…` 버튼을 잡는 flake 는 대기 헬퍼(`waitAnalyzeButton`)로 없앤다.
8. **회귀 방지선을 남긴다**: 단위(뜻·분할 교정 6건) + 화면 스모크(`view:notes 구문 뜻 표시`).

## 16차 라운드 (빌드 패키징 + 자동 업데이트)

사용자 요청: "버전 업그레이드 되면 자동으로 다운로드 받을 수 있도록 홈상단에 버전표시 해주고, 업데이트 있으면 있다고 표기하고 누르면 다운로드 되서 업데이트 되도록".

### 범위

1. 배포 패키징: `electron-builder` NSIS 설치본 + 아이콘 + yt-dlp 번들 (T49)
2. 자동 업데이트: 홈 상단 버전 표시, 피드 확인, 다운로드, 설치 후 재시작 (T50)
3. 검증: 단위 테스트(업데이트 로직), 스모크(배너·설정 카드), 실제 `npm run dist`

### 설계 원칙

1. **통신은 메인 프로세스에서만 한다**: 렌더러는 loopback HTTP + CSP(`connect-src 'self' youtube`) 라서 외부 요청이 막힌다. 업데이트 확인·다운로드를 렌더러에 두면 CSP 와 씨름하게 되므로, 전부 `main/update.js`(Node `https`)에서 하고 렌더러에는 `update:status` 이벤트로 상태만 보낸다. 이벤트도 `mainWindow.webContents.send` 로만 보낸다.
2. **피드는 사용자가 정한다**: 자체 업데이트 서버를 내장하지 않는다. 설정에 넣은 JSON 주소를 읽고, 주소가 없거나 `http`/`https` 가 아니면 **자동 확인도 하지 않는다**(불필요한 요청·오류 로그 방지). 상대 경로 자산 URL 은 피드 주소 기준으로 해석해 정적 호스팅에 설치본과 `latest.json` 만 올리면 되게 한다.
3. **받은 파일을 믿기 전에 검증한다**: `sha256` 이 피드와 다르면 `ready` 로 넘어가지 않고 `.part` 를 지운다(`UPDATE_HASH`). 부분 다운로드가 설치로 이어지는 경로를 아예 만들지 않는다.
4. **중간 상태를 화면에 그대로 보여 준다**: 버전·상태 문구·진행률(%)을 상태 머신(`idle/checking/current/available/downloading/ready/installing/error`)에서 파생시킨다. 별도 렌더러 상태를 만들지 않아 화면과 실제 상태가 어긋나지 않는다.
5. **설치 스크립트의 인용 규칙을 지킨다**: NSIS 의 `/D=<경로>` 는 **줄 끝까지**가 경로다. 같은 줄에 `&&` 등으로 다른 명령을 붙이면 경로가 오염되므로 `start /wait` · `start exe` · `del` 을 각각 별도 줄로 쓴다. 테스트로 이 규칙을 고정한다.
6. **개발 실행과 설치본을 구분한다**: `app.isPackaged === false` 면 설치할 대상이 없으므로 `UPDATE_DEV` 로 막는다. 배너도 이 경우 다운로드 버튼을 숨기지 않되 설치 단계에서 이유를 알려 준다.
7. **설정을 바꾸면 이전 상태를 버린다**: 피드 주소를 지우거나 다른 곳으로 바꾸면 이전 버전의 `latest`·진행률이 남아 있으면 안 된다. `clearLatest()` 로 비우고 `idle` 로 되돌린다(다운로드·설치 중에는 유지).
8. **번들 바이너리는 탐색 순서로 해결한다**: yt-dlp 를 `extraResources` 로 `resources/bin` 에 넣고, 탐색 순서에 그 경로를 추가한다. 사용자가 설정에서 지정한 경로가 항상 1순위다.
9. **회귀 방지선을 남긴다**: 피드/다운로드는 로컬 HTTP 서버 + `electron` 모듈 스텁으로 단위 테스트하고(주소 없음·`ftp://` 거부, 302 추적, sha256 불일치, 주소 삭제 시 상태 초기화, 자동 확인 요청 0회, `/D=` 한 줄 규칙), 화면은 스모크로 확인한다.

2. **기본값은 "동작하는 주소"**: 사용자가 아무것도 하지 않아도 업데이트가 확인되도록 기본 피드 주소를 코드에 넣는다. 값은 DB 행이 없을 때만 쓰이므로 사용자가 바꾼 주소를 덮어쓰지 않는다.
3. **주소 변경 → 재빌드 순서를 지킨다**: 기본 주소는 `app.asar` 안에 들어가므로, 주소를 바꾼 뒤 **다시 빌드한 설치본**을 올려야 한다(빌드 → 주소 변경 순서로 하면 배포본에 옛 기본값이 남는다).
4. **자산 URL 은 상대 경로로 둔다**: `latest.json` 의 `url` 을 절대 주소로 굳히면 저장소 이름·미러 변경 때 피드까지 고쳐야 한다. `new URL(value, feedUrl)` 해석이 `releases/latest/download/` 아래에서도 같은 폴더를 가리키는 것을 실제 응답으로 확인했다.
5. **배포는 한 명령으로**: 사람이 하는 일은 버전 올리기와 설명 쓰기뿐이고, 빌드·업로드·덮어쓰기 판단은 `scripts/release.js` 가 한다. 실패하면 어느 단계에서 멈췄는지 한국어로 알려 준다.
6. **인자 인용은 런타임에 맡긴다**: `gh`·`git` 은 `shell:false`(Node 가 인용), `npm` 은 `.cmd` 라서 `shell:true`. 셸 문자열 조립으로 `--title StudyTED v1.0.0` 같은 인자를 만들면 공백에서 쪼개진다.
7. **커밋 전 비밀 점검**: `_workspace/*.md`·`README.md` 에 `sk-or-` 패턴이 0건임을 확인하고, `git diff --cached --name-only` 로 `.env` 가 없는지 눈으로 확인한 뒤 커밋한다.
