# Study_ted — YouTube 영어 학습 데스크톱 앱

유튜브 채널을 등록하면 **영상 제목·주소·자막**을 순차적으로 수집하고, 그 자막을 재료로 **듣기 / 자막 학습 / 문장 노트 / AI 구문분석**을 제공하는 Electron + SQLite 데스크톱 앱입니다.

## 요구 사항

- Windows 10/11 (개발·검증 환경)
- Node.js 22 이상 (`node:sqlite` 내장 모듈 사용, 별도 DB 설치 불필요)
- 설치된 의존성: `electron` (devDependency)

## 설치

    npm install

## 실행

| 명령 | 설명 |
|---|---|
| `npm start` | 빈 상태로 앱 실행 |
| `npm run dev` | 개발자 도구를 연 상태로 실행 |
| `npm run demo` | UI 목업과 같은 데모 데이터를 넣고 실행 |

앱은 프레임리스 창(자체 타이틀바)으로 뜨며, 창을 닫으면 종료됩니다.

## 주요 기능

1. **채널 수집** — 상단 입력창에 `https://www.youtube.com/@channelname` 형태의 채널 주소를 넣고 **채널 불러오기**를 누르면 채널 정보 + 영상 목록 + 영어 자막을 순서대로 수집합니다. 기본값은 **채널 전체 수집**(개수 제한 없음)이며, 진행률은 하단 로그/진행 표시로 보여줍니다.
2. **듣기 모드** — 영상만 재생합니다(자막 꺼짐).
3. **자막 모드** — 플레이어 자막을 켜고, 오른쪽 **전체 자막** 패널에서 현재 재생 중인 문장을 하이라이트하고 자동 스크롤합니다. 자막 줄을 클릭하면 그 지점으로 이동해 **바로 재생**되고, 줄마다 있는 **문장 전송** 버튼을 누르면 그 문장이 오른쪽 문장 노트 입력칸으로 전송됩니다(입력칸은 **지워지지 않고 줄 단위로 쌓이며**, 이미 들어 있는 문장은 중복 추가하지 않습니다).
4. **문장 저장** — 자막에서 문장을 클릭/선택해 **문장 노트**에 저장합니다. 영어 원문·해석·출처(영상 제목/주소)가 함께 저장됩니다.
5. **AI 구문분석** — 저장한 문장에 대해 OpenRouter 모델로 (1) 한국어 해석 (2) 구문 분석(영어 구문 + 한국어 설명)을 받아옵니다. 문장을 저장하지 않고 **AI 구문분석**을 눌러도 그 문장으로 바로 분석해 **자동 저장하고 결과를 즉시 보여줍니다**(한 번에 최대 5문장, 진행 중 `분석 중… i/n` 표시). AI를 쓰지 않고 **수동 입력**으로 직접 채우는 것도 가능합니다.
6. **학습 자료 목록** — 저장한 문장을 표로 계속 누적합니다. 검색, 채널 필터, 정렬, 즐겨찾기를 지원합니다.
7. **공유** — 문장 노트를 JSON / Markdown / HTML 로 내보내고, JSON 을 다시 가져와 병합할 수 있습니다.
8. **설정** — OpenRouter API 키, 모델 선택, 자주 쓰는 모델·즐겨찾기 모델, yt-dlp 경로/다운로드, **채널 전체 수집**(끄면 수집 개수 제한 사용), 자막 수집 여부, **자막 동시 수집 개수**(기본 4, 1~8, 1이면 순차), **기존 영상 정보 다시 가져오기**, 모델별 **가격 표시**(1M 토큰당 USD)·**가성비 추천**·**모델 검색**.
9. **버전 표시와 자동 업데이트** — **홈 화면 맨 위**에 `StudyTED v1.0.0` 처럼 현재 버전이 표시되고, 설정에 넣은 업데이트 주소(`latest.json`)를 시작 8초 후와 6시간마다 조용히 확인합니다. 새 버전이 있으면 `새 버전 v… 이 있습니다` 로 바뀌고, **업데이트 내려받기 → 지금 설치하고 다시 시작** 을 누르면 설치 후 앱이 다시 열립니다(`sha256` 검증, 부분 다운로드 자동 삭제). 설정 → 업데이트 에서 주소·자동 확인·조용한 설치를 바꿀 수 있습니다. **업데이트 주소에는 GitHub 릴리스 주소가 기본으로 들어 있어** 설치만 하면 바로 동작합니다. 배포 방법은 **빌드와 배포** 절을 보세요.
10. **채널 관리에서 다시 수집** — 등록된 채널 행마다 **수집** 버튼이 있어 그 채널만 다시 가져올 수 있고, 목록 헤더의 **전체 채널 수집** 버튼은 등록된 채널을 모두 순차 수집합니다. 각 채널 행에는 지금까지 모은 `수집 동영상 N개 · 자막 N개 · 저장 문장 N개` 가 함께 표시되고, 수집이 끝나면 개수가 갱신됩니다. 진행 중에는 `(i/n)` 진행 바와 행별 상태(`수집 중…` → `완료 · 신규 N개 · 자막 M개` / `실패 · 사유` / `취소됨`)가 표시되고, 수집 중에는 다른 수집 버튼이 잠기면서 진행 바 옆에 **수집 정지** 버튼이 나타납니다.

- **재수집 동작** — 같은 채널을 다시 불러올 때 **기존 영상 정보 다시 가져오기**(`refreshExisting`, 기본 켜짐)가 켜져 있으면 제목·조회수·썸네일을 최신값으로 갱신하고, 끄면 기존 영상은 그대로 두고 **새로 올라온 영상만** 저장합니다. 어느 쪽이든 이미 받은 자막은 다시 받지 않습니다.
- **동영상 선택 목록** — 학습하기의 동영상 목록은 채널 전체(2,000편 이상도)를 **50편 단위 페이징**으로 보여줍니다. 채널 선택 드롭다운 바로 아래 **검색창**에 제목 일부를 넣으면 제목·설명을 기준으로 걸러내고(입력 후 0.26초 디바운스, Enter 는 즉시), 목록 위에는 `전체 N개 중 i–j` / `검색 결과 N개 중 i–j` 가 표시됩니다. 필터링은 SQLite 에서 처리하므로 영상이 많아도 부하가 걸리지 않습니다.
- **수집 범위와 정지** — 기본값은 채널 전체 수집입니다. 채널이 크면 오래 걸리므로 진행 표시를 보며 **수집 정지** 버튼으로 언제든 멈출 수 있습니다. 정지를 누르면 진행 중인 요청과 자식 프로세스가 그 자리에서 끊기고, **그때까지 받은 영상·자막은 그대로 남습니다**(취소된 채널 행은 `취소됨`). 빠르게 확인하고 싶다면 **설정 → 채널 전체 수집**을 끄고 수집 개수(예: 24)를 지정하세요.

## 데이터 저장 위치

| 항목 | 경로 |
|---|---|
| SQLite DB | `%APPDATA%\study-ted\study-ted.db` |
| 로그 | `%APPDATA%\study-ted\logs\app.log` |
| yt-dlp(앱에서 내려받은 경우) | `%APPDATA%\study-ted\bin\yt-dlp.exe` |
| 수집 임시 폴더 | `%APPDATA%\study-ted\tmp\` |
| 업데이트 내려받기 | `%APPDATA%\study-ted\tmp\updates\` (다운로드 중에는 `.part`, 검증 통과 후 설치 파일) |

프로젝트 폴더는 데이터로 오염되지 않습니다. 검증 스크립트는 별도 userData(`_tmp\smoke-userdata`, `_tmp\e2e-userdata`, `_tmp\e2e-player-userdata`)를 사용합니다.

## 자막 수집과 yt-dlp

- 1순위는 **yt-dlp** 입니다. yt-dlp 가 있으면 영상 목록·메타데이터·자막을 안정적으로 가져옵니다.
- yt-dlp 가 없으면 **native 모드**(YouTube HTML/Innertube 파싱)로 폴백합니다. 채널 등록·영상 목록·재생은 동작하지만, **자막 본문은 YouTube 의 봇 차단으로 실패할 수 있습니다.** 이 경우 설정 화면에서 yt-dlp 경로를 지정하거나 **yt-dlp 다운로드** 버튼을 사용하세요.
- 설정의 `provider` 값으로 `auto` / `ytdlp` / `native` 를 강제할 수 있습니다.
- 자막은 영상 여러 편을 **동시에** 내려받습니다(**설정 → 수집 설정 → 동시 수집 개수**, 기본 4). 실측(TED 6편)에서 순차 대비 **2.29배** 빨랐습니다. YouTube 가 제한을 걸면 1 로 낮춰 순차 수집하세요.

## OpenRouter API 키

- 키는 렌더러에서만 입력받고, 메인 프로세스에서 `safeStorage` 로 암호화해 DB에 저장합니다. 화면에는 마스킹된 값과 저장 시각만 표시됩니다.
- 키 원문은 로그·문서·`_workspace` 기록에 남기지 않습니다.
- 저장된 키는 **연결 테스트**로 확인할 수 있고, 형식이 `sk-or-` 로 시작하지 않으면 저장이 거부됩니다.

## 검증

    npm test                 # 단위 테스트 (문법/DB/응답 파싱/AI 정규화)
    npm run smoke            # Electron 부팅 + IPC + 뷰 스크린샷 (오프라인)
    npm run e2e -- --url=https://www.youtube.com/@TED --limit=2   # 실제 채널 수집 E2E
    npm run e2e:player                                           # 실제 영상 임베드 재생 E2E

주의(Windows/PowerShell):

- `ELECTRON_RUN_AS_NODE=1` 이 설정된 셸에서는 Electron 이 순수 Node 로 실행되어 스크립트가 실패합니다. 실행 전에 `Remove-Item Env:\ELECTRON_RUN_AS_NODE` 로 지우세요.
- 스크립트에 URL 을 넘길 때는 위치 인자가 아니라 `--url=<주소>` 형식을 사용합니다.
- `npm run e2e` 는 네트워크와 실제 자막 제공 여부에 의존하므로 실패할 수 있습니다. 대상은 `--url=`, 개수는 `--limit=`, provider 는 `--native` 또는 `STUDY_TED_E2E_URL` 로 바꿉니다.
- **PowerShell 에서 `npm run e2e` 로 실행하면 `--url=` / `--limit=` 인자가 전달되지 않아 기본 개수(3)로 돕니다.** 정확한 개수로 확인하려면 `node_modules\.bin\electron.cmd scripts\e2e-collect.js "--url=https://www.youtube.com/@TED" "--limit=6" "--fresh"` 처럼 직접 실행하세요.
- `npm run e2e:player` 는 실제 YouTube 영상 1개를 임베드로 재생해 Referer 전달·재생 오류·재생 시간을 확인합니다(기본 영상 `PRmIrFhce04`, `--video=<영상ID>` 로 변경).
- `npm run e2e` 는 빠른 회귀 확인을 위해 `--limit=2` 로 실행합니다. 채널 전체 수집(기본값)은 앱 화면의 **채널 불러오기** / **채널 관리 → 전체 채널 수집** 으로 확인하세요.

## 빌드와 배포

Windows 설치본(NSIS)을 만들어 배포하고, 설치된 앱이 스스로 새 버전을 찾아 업데이트하게 할 수 있습니다.

    npm run icon          # 아이콘 생성 (build/icon.png · build/icon.ico)
    npm run prepare:bin   # _tmp\yt-dlp.exe → build/bin/yt-dlp.exe (설치본에 함께 실림)
    npm run dist          # 설치본 + dist\latest.json 생성
    npm run dist:dir      # 설치 없이 dist\win-unpacked 폴더만 (빠른 확인용)
    npm run manifest      # 설치본은 그대로 두고 dist\latest.json 만 다시 생성
    npm run release       # 빌드 + GitHub 릴리스 업로드 (설치본 · blockmap · latest.json)

- 산출물: `dist\StudyTED-Setup-<버전>.exe`, `dist\StudyTED-Setup-<버전>.exe.blockmap`, `dist\latest.json`
- 버전은 `package.json` 의 `version` 을 따릅니다. 새 버전을 낼 때는 **`version` 을 올리고 `npm run dist` 를 다시 실행**하세요.
- 바탕화면·시작 메뉴 바로가기(`StudyTED`)가 만들어지고, 설치 폴더를 바꿀 수 있습니다(사용자 단위 설치, 관리자 권한 불필요).
- 제거해도 **학습 데이터는 지워지지 않습니다**(`%APPDATA%\study-ted`). 완전 삭제는 직접 폴더를 지우면 됩니다.
- 빌드 중 `dist` 파일이 잠겨 실패하면 실행 중인 `StudyTED`/`study-ted` 프로세스를 모두 닫고 다시 실행하세요.

### GitHub 릴리스로 배포 (기본 경로)

이 프로젝트의 설치본은 **GitHub 릴리스**로 배포하고, 앱이 그 릴리스를 보고 스스로 업데이트합니다.

- 저장소: <https://github.com/pang980/study-ted> (소스 공개)
- 릴리스: <https://github.com/pang980/study-ted/releases/latest>
- 앱에 내장된 기본 업데이트 주소: `https://github.com/pang980/study-ted/releases/latest/download/latest.json`

새 버전을 낼 때는 다음 순서면 됩니다.

    npm version 1.0.1 --no-git-tag-version   # package.json 버전 올리기
    # build\release-notes.md 에 새 버전 설명 적기 (건너뛰면 이전 설명이 그대로 올라갑니다)
    npm run release                          # 빌드 + v1.0.1 릴리스 생성(또는 갱신) + 자산 업로드

`npm run release`(`scripts/release.js`) 는 `npm run dist` 로 설치본을 만든 뒤 [GitHub CLI](https://cli.github.com/) 로 **설치본 · blockmap · latest.json** 을 올립니다. 같은 태그가 이미 있으면 파일만 덮어씁니다(`--clobber`). 업로드가 끝나면 설치된 앱이 홈 배너에서 새 버전을 알려 주고, **업데이트 내려받기 → 지금 설치하고 다시 시작** 한 번으로 갱신됩니다.

- `latest.json` 의 `url` 은 파일명만 들어갑니다. 앱이 피드 주소를 기준으로 절대 주소를 만들기 때문에 `releases/latest/download/...` 에서도 그대로 동작합니다.
- 릴리스가 곧 배포 서버라서 설치본과 `dist\` 는 저장소에 커밋하지 않습니다(`.gitignore`).
- 배포하려면 GitHub CLI 로그인(`gh auth login`)과 `origin` 원격 저장소가 필요합니다(스크립트가 먼저 확인합니다).
- 저장소를 비공개로 바꾸면 로그인 없이 받을 수 없어 **자동 업데이트가 동작하지 않습니다.** 그때는 직접 호스팅한 `latest.json` 주소를 **설정 → 업데이트 → 업데이트 주소** 에 넣어 쓰세요.

### 업데이트 배포

1. `dist\StudyTED-Setup-<버전>.exe` 와 `dist\latest.json` 을 **같은 위치**에 올립니다(정적 호스팅, GitHub Releases 자산 등).
2. `latest.json` 형식(설치본과 같은 폴더에 두면 `url` 은 파일명만 써도 됩니다):

```json
{
  "version": "1.0.1",
  "pubDate": "2026-10-01T00:00:00.000Z",
  "url": "StudyTED-Setup-1.0.1.exe",
  "sha256": "<설치본의 SHA256>",
  "size": 128832424,
  "notes": "1.0.1 버전입니다."
}
```

3. 앱 **설정 → 업데이트** 에 `latest.json` 주소를 넣고 저장합니다(예: `https://example.com/studyted/latest.json`). **기본값은 위 GitHub 릴리스 주소**이므로 그대로 두면 됩니다.
4. 앱은 시작 8초 후와 6시간마다 조용히 확인하고, 새 버전이 있으면 **홈 화면 맨 위 배너**가 `새 버전 v1.0.1 이 있습니다` 로 바뀝니다. 배너의 **업데이트 내려받기** → **지금 설치하고 다시 시작** 을 누르면 다운로드·설치 후 앱이 다시 열립니다.
5. 내려받은 파일은 `sha256` 이 피드와 다르면 설치되지 않습니다(부분 다운로드는 자동 삭제).

- 피드 주소를 비우면 자동 확인을 하지 않습니다(안내 문구만 표시).
- 개발 모드(`npm start`)에서는 설치할 대상이 없어 설치 단계에서 안내 메시지가 나옵니다(다운로드 확인은 가능).
- 코드 사이닝을 하지 않았으므로 Windows SmartScreen 경고가 뜰 수 있습니다.

## 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| 자막이 저장되지 않음 | YouTube 가 자막 본문 전송을 차단(native 모드) | 설정에서 yt-dlp 경로 지정 또는 다운로드 |
| `yt-dlp 를 찾을 수 없습니다` | yt-dlp 미설치 + provider 가 `ytdlp` 로 고정 | provider 를 `auto` 로 바꾸거나 yt-dlp 설치 |
| 영상은 보이는데 자막 패널이 비어 있음 | 해당 영상에 영어 자막이 없음 | 다른 영상을 선택하거나 자막 수집을 다시 실행 |
| AI 구문분석이 실패 | 키 미저장/만료, 모델 미선택, 네트워크 오류 | 설정에서 키 저장 후 **연결 테스트**, 모델 선택 |
| 앱이 창 없이 즉시 종료 | `ELECTRON_RUN_AS_NODE=1` 환경변수 | 위 검증 항목의 조치 참고 |
| 창이 검게 나오거나 화면이 깨짐 | GPU 합성 문제(간헐적) | `npm start -- --disable-gpu` 로 실행해 확인 |
| "동영상을 재생하지 못했습니다" | (수정됨) 커스텀 스킴으로 렌더러를 열 때 `Referer` 누락 → 임베드 거부 | 최신 버전은 loopback HTTP 로 서빙합니다. `npm run e2e:player` 로 확인 |
| 특정 영상만 재생 불가 | 영상 자체의 임베드 제한(101/150) 또는 삭제·비공개(100) | 재생 영역에 표시된 코드별 안내를 확인하고 다른 영상 선택 |
| 자막을 수천 개 받는 중에 멈추고 싶음 | 채널 전체 수집(기본값)은 영상 1개마다 yt-dlp 를 호출해 오래 걸림 | 진행 바 옆 **수집 정지** 로 중단(그때까지 받은 자료는 유지). 빠른 확인은 **설정 → 채널 전체 수집** 해제 후 개수 지정 |
| 데모 데이터의 영상이 재생되지 않음 | 데모는 실제 YouTube ID 가 아님(`demoVideo001`) | **설정 → 데모 데이터 삭제** 후 실제 채널을 불러오기 |
| 채널을 불러왔는데 영상이 24개만 들어옴 | (수정됨) 기본 수집 개수 제한 24 | 최신 버전은 **채널 전체 수집**이 기본입니다. 예전 설정이 남아 있으면 **설정 → 채널 전체 수집**을 켜세요 |
| 창을 확대/축소하면 화면이 검은 막으로 덮임 | (수정됨) 자막 오버레이가 플레이어 프레임 전체를 덮던 CSS 규칙 | 최신 버전에서 수정되었습니다. 자막은 영상 하단의 내용 크기 상자로 표시됩니다 |
| 자막 수집이 너무 오래 걸림 | 영상 1편씩 순차로 받으면 편당 9~11초가 걸림 | **설정 → 수집 설정 → 동시 수집 개수**를 4~8로 올리기(기본 4). YouTube 제한이 걸리면 1 로 낮추기 |
| 자막 줄을 여러 개 전송했는데 하나만 남음 | (수정됨) 전송이 입력칸을 덮어썼음 | 최신 버전은 줄 단위로 **누적**되고 중복은 무시합니다 |
| AI 를 눌렀는데 결과가 저장되지 않음 | (수정됨) 저장된 문장만 분석 대상이었음 | 최신 버전은 **저장하지 않아도 분석 즉시 자동 저장**됩니다 |
| AI 분석 결과(해석·구문분석)가 문장 노트에 안 보임 | (수정됨) 목록에 분석을 그리는 자리가 없었음 | 최신 버전은 문장 노트의 `분석` 컬럼에서 `분석 보기` 로 펼쳐 봅니다. 예전에 저장된 문장은 분석이 비어 있으니 다시 분석하세요 |
| AI 구문분석이 자주 실패함("요청이 너무 많습니다") | 무료 모델의 사용량 제한(429)을 재시도 없이 그대로 실패 처리 | 최신 버전은 자동으로 재시도합니다. 계속 실패하면 **설정 → 모델**에서 유료/다른 모델을 선택하세요 |
| 학습하기 동영상 목록이 200개만 보임 | (수정됨) 렌더러가 `limit:200` 으로 한 번에 요청 | 최신 버전은 검색 + 50편 페이징으로 **채널 전체**를 봅니다 |
| 채널 관리에서 `수집 환경` 카드가 안 보임 | (수정됨) 진단용 카드는 기본 숨김 | yt-dlp 미설치 등으로 **수집이 불가능할 때만** 자동 표시됩니다. 같은 정보는 설정 화면에 있습니다 |
| 자막 패널의 자막과 플레이어 자막 위치가 다름 | 플레이어 자막은 오버레이, 오른쪽 패널은 전체 자막 | 자막 모드에서 둘 다 표시하는 것이 정상입니다. 자막만 끄려면 듣기 모드를 사용하세요 |
| AI 구문분석 결과가 전부 한국어로 보임 | (수정됨) 소형 모델이 영어로 나와야 할 구문(`part`)까지 한국어로 채움 | 최신 버전은 프롬프트에 "영어 필드는 영어로" 규칙을 넣고 응답을 검사해 **1회 자동 교정**합니다. 그래도 한국어가 남으면 분석 카드 위에 노란 경고로 알리고, **설정 → 모델**에서 더 큰 모델을 선택하세요 |
| 분석 카드에 `AI 원문 응답`·주요 표현·예문이 안 보임 | (변경) 카드는 **문장 해석 · 구문 분석** 두 가지만 표시 | 사용자 요청으로 화면에서 제거했습니다. `analysis.raw`(원문 응답)는 DB 에 그대로 남고, 새로 분석할 때 표현·예문은 요청하지 않습니다 |
| 문장 노트의 태그·메모 입력칸이 사라짐 | (변경) 태그·메모 기능 제거 | 사용자 요청으로 `sentences.note` 컬럼과 `tags`·`sentence_tags` 테이블을 실제로 삭제했습니다. 앱을 다시 켜면 자동 마이그레이션되며 **저장된 문장·해석·분석은 그대로 유지**됩니다 |
| 홈 배너에 `업데이트 주소를 설정하면 …` 만 보임 | (정상) 업데이트 주소가 비어 있음 | **설정 → 업데이트 → 업데이트 정보 주소** 에 `latest.json` 주소를 넣고 저장하세요. 주소를 넣지 않으면 자동 확인을 하지 않습니다 |

| `지금 설치하고 다시 시작` 을 눌러도 설치가 안 됨 | 개발 모드(`npm start`)이거나 내려받은 파일이 없음 | 패키징된 설치본에서만 조용한 설치가 동작합니다. 먼저 **업데이트 내려받기** 로 파일을 받은 뒤 설치하세요 |
| 구문이 `Along / with / their / research` 처럼 단어로 쪼개지고 한국어 뜻이 없음 | (수정됨) 소형 모델이 문장을 단어 단위로 나누고 `meaning` 을 비움 | 최신 버전은 구문을 **의미 덩어리 3~6개**로 묶고 각 항목에 **한국어 뜻**을 요구하며, 응답을 검사해 1회 자동 교정합니다. 이미 저장된 문장은 문장 노트의 `AI 다시 분석` 버튼으로 갱신하세요 |

## 폴더 구조

    main/            Electron 메인 프로세스 (창, IPC, DB, 수집, AI, 공유)
      db/            SQLite 스키마·쿼리
      collect/       자막/영상 수집 (yt-dlp · native)
      ai/            OpenRouter 연동
    renderer/        UI (HTML/CSS/JS, 뷰 7종 + 공용 컴포넌트)
    scripts/         smoke / e2e 검증 스크립트 + 빌드·배포 보조(아이콘·yt-dlp·latest.json·릴리스 업로드)
    test/            단위 테스트
    build/           아이콘 + 설치본에 실릴 yt-dlp (빌드 리소스)
    dist/            빌드 산출물 (설치본 + latest.json)
    rules/           편집·코딩·검증 규칙
    _workspace/      하네스 산출물 (입력/분석/계획/검증/결정 기록)

## 보안

- 렌더러는 `contextIsolation` + preload 화이트리스트 API 만 사용하며 Node API 에 직접 접근하지 않습니다.
- 렌더러는 `http://127.0.0.1:<임의 포트>`(루프백 전용)로만 서빙되며, 창 내 이동은 그 범위로 제한됩니다. 그 밖의 링크는 기본 브라우저로 넘깁니다. 렌더러에는 CSP 헤더가 적용됩니다.
- 커스텀 스킴(`app://`)을 쓰지 않는 이유: Chromium 이 커스텀 스킴 요청에 `Referer` 를 붙이지 않아 YouTube 임베드가 재생을 거부(`error 153`)합니다.
- `.env` 는 앱이 읽지 않습니다(개발자 개인 파일). 앱에서 쓰는 키는 설정 화면에서 입력합니다.
